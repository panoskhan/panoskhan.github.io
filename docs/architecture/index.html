Architecture overview

Phase 2 of Project Atlas extends the live site into a maintainable digital ecosystem. Existing pages stay online; new products plug into one design system and one navigation shell.

Principles

  • Extend, do not redesign: homepage identity and completed work remain intact.
  • One ecosystem: every product reuses shell, tokens, cards, and SEO patterns.
  • No duplicate sources of truth: registries and shared CSS/JS own cross-cutting concerns.
  • Static-first: GitHub Pages compatible, minimal JavaScript, progressive enhancement.
  • Safe by default: Device and Downloads content stays lawful guidance and transparent assets only.

Product architecture

Core site

Home, About, Services, Research, Projects, Blog, Credentials, Contact.

Products

AI, Device Service, Downloads, Labs, Docs — plus Research, Open Source, Capabilities, Projects.

Future slots

Academy, Community, Console, API, Cloud — reserved, not shipped.

Folder structure

/assets
  /css /js /images /icons /data /downloads /components
/ai /device /downloads /research /projects /docs /labs
/open-source /capabilities
/templates /schema
/scripts

Canonical Device Service path remains /device/ to preserve live links. Product name in UI is “Device Service”.

Design system

Tokens and components live in assets/css/main.css. Product-specific polish (AI tools) may add a thin layer such as ai-platform.css without forking the brand.

  • Glass cards, premium typography, consistent spacing
  • Accessible contrast on the dark theme
  • Minimal motion; reduced-noise interactions
  • Future light mode can flip CSS custom properties without markup rewrites

Data layer

  • /assets/data/products.json — product registry and nav roles
  • /assets/data/search-index.json — global client-side search corpus
  • /assets/data/downloads.json — download catalog + safety policy
  • /assets/data/capabilities.json — capability explorer catalog

SEO & accessibility

Every public page targets title, description, canonical, Open Graph, Twitter Card, JSON-LD (including breadcrumbs), semantic landmarks, keyboard access, visible focus, and WCAG AA contrast.

Performance

No SPA framework. Shared CSS/JS are cacheable. Images use explicit dimensions where present. Search and shell mount progressively. Target: Lighthouse 95+ on content pages with lean assets.

Scalability

New tools become files under a product folder plus registry entries. New articles attach to Research or Docs. Downloads append to downloads.json. Search grows through the JSON index instead of hard-coding every page script.

Roadmap after this foundation

  • v4.0 — AI Platform depth (agents reserved until catalog/docs mature)
  • v4.5 — Device Service interactive decision trees
  • v5.0 — Downloads hub filters and printable assets
  • v6.0 — Workspace dashboard concept
  • v7.0 — Optional cloud/auth only if leaving pure static hosting
